Claude Code 全自動運営キット

AI社長ラボ（Claudeが経営するビジネス実験）で実際に動いているコード・運用ルール・失敗集を、そのまま抜き出したものです。

正直に書いておくこと
・このキットは「動いているもの」を載せています。売上や収益を保証するものではありません。実験開始2日目時点で売上は0円です。
・APIキー等の秘密情報は一切含まれません。あなた自身のキーを .env に置いて使います。
・X APIは従量課金です（実測：URLなし $0.015/件、URL付き $0.20/件）。

0. 全体構成

Claude Code（CEO）
  ├─ Stripe（決済・商品・Payment LinkをAPIで作成）
  ├─ GitHub Pages（サイト。Contents APIでgit無しにデプロイ）
  ├─ X API（投稿。キューから1件ずつ、Windowsタスクスケジューラで9:00/21:00）
  ├─ Dev.to API（記事の自動投稿）
  └─ 毎朝の実測（GitHub Traffic / Stripe を叩いて、KPI.md とサイトを更新）
人間の仕事：本人確認・支払い承認・アカウント作成・固定ポストなどの「1操作」だけ

1. x_post.py（X API v2への投稿ヘルパー）

標準ライブラリのみ。OAuth1.0a署名を自前実装。失敗時は必ず例外を出すのが要点です（失敗集 #3）。prefixで別アカウントの認証情報、reply_toで自己リプ投稿ができます。

# -*- coding: utf-8 -*-
"""X API v2 投稿ヘルパー（標準ライブラリのみ、OAuth1.0a自前署名）。

- 失敗時は例外を送出する（呼び出し側が「成功時のみキューから消す」ために必須）
- prefix を指定すると別アカウントの認証情報を使える（例: prefix="TOMOKI_" → TOMOKI_X_API_KEY 等）
- reply_to を指定するとそのツイートへの返信として投稿する（URL付き本文を自己リプに分離する用途）
"""
import base64
import hashlib
import hmac
import json
import random
import string
import sys
import time
import urllib.error
import urllib.parse
import urllib.request

API_URL = "https://api.x.com/2/tweets"


def load_env(path):
    env = {}
    with open(path, encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if not line or line.startswith("#") or "=" not in line:
                continue
            k, v = line.split("=", 1)
            env[k.strip()] = v.strip()
    return env


def _enc(s):
    return urllib.parse.quote(str(s), safe="")


def oauth1_header(method, url, api_key, api_secret, token, token_secret):
    oauth_params = {
        "oauth_consumer_key": api_key,
        "oauth_nonce": "".join(random.choices(string.ascii_letters + string.digits, k=32)),
        "oauth_signature_method": "HMAC-SHA1",
        "oauth_timestamp": str(int(time.time())),
        "oauth_token": token,
        "oauth_version": "1.0",
    }
    # JSONボディはOAuth署名対象に含めない
    param_str = "&".join(f"{_enc(k)}={_enc(v)}" for k, v in sorted(oauth_params.items()))
    base_str = "&".join([method.upper(), _enc(url), _enc(param_str)])
    signing_key = f"{_enc(api_secret)}&{_enc(token_secret)}"
    oauth_params["oauth_signature"] = base64.b64encode(
        hmac.new(signing_key.encode(), base_str.encode(), hashlib.sha1).digest()
    ).decode()
    return "OAuth " + ", ".join(f'{_enc(k)}="{_enc(v)}"' for k, v in sorted(oauth_params.items()))


def post_tweet(env, text, prefix="", reply_to=None):
    """投稿して tweet id を返す。HTTPエラー時は RuntimeError。"""
    header = oauth1_header(
        "POST", API_URL,
        env[f"{prefix}X_API_KEY"], env[f"{prefix}X_API_SECRET"],
        env[f"{prefix}X_ACCESS_TOKEN"], env[f"{prefix}X_ACCESS_TOKEN_SECRET"],
    )
    payload = {"text": text}
    if reply_to:
        payload["reply"] = {"in_reply_to_tweet_id": str(reply_to)}
    req = urllib.request.Request(API_URL, data=json.dumps(payload).encode("utf-8"), method="POST")
    req.add_header("Authorization", header)
    req.add_header("Content-Type", "application/json")
    try:
        with urllib.request.urlopen(req) as resp:
            return json.loads(resp.read().decode("utf-8"))["data"]["id"]
    except urllib.error.HTTPError as e:
        raise RuntimeError(f"HTTP {e.code}: {e.read().decode('utf-8', 'replace')}") from e


if __name__ == "__main__":
    # usage: python x_post.py <env_path> <text> [prefix] [reply_to_id]
    env = load_env(sys.argv[1])
    print(post_tweet(env, sys.argv[2],
                     prefix=sys.argv[3] if len(sys.argv) > 3 else "",
                     reply_to=sys.argv[4] if len(sys.argv) > 4 else None))

2. daily_post.py（キューから1件投稿。成功時のみ消す）

marketing/post_queue.txt に1行1投稿で並べておくと、1件ずつ投稿して消化します。失敗した行は残り、post_log.txt にエラーが残ります。

# -*- coding: utf-8 -*-
import os
import sys
import datetime

BASE = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
sys.path.insert(0, BASE)

QUEUE_PATH = os.path.join(BASE, "marketing", "post_queue.txt")
LOG_PATH = os.path.join(BASE, "marketing", "post_log.txt")
ENV_PATH = os.path.join(BASE, ".env")

sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
import x_post  # marketing/x_post.py（失敗時は例外を送出するので、失敗した投稿はキューに残る）


def main():
    if not os.path.exists(QUEUE_PATH):
        print("queue file not found")
        return

    with open(QUEUE_PATH, encoding="utf-8") as f:
        lines = [l.rstrip("\n") for l in f]
    lines = [l for l in lines if l.strip()]

    if not lines:
        print("queue is empty, nothing to post")
        return

    text = lines[0]
    remaining = lines[1:]

    env = x_post.load_env(ENV_PATH)

    try:
        x_post.post_tweet(env, text)
        ok = True
    except Exception as e:
        ok = False
        with open(LOG_PATH, "a", encoding="utf-8") as f:
            f.write(f"{datetime.datetime.now().isoformat()} ERROR: {e} | text={text}\n")
        print("post failed, keeping in queue:", e)
        return

    # only remove from queue on success
    with open(QUEUE_PATH, "w", encoding="utf-8") as f:
        f.write("\n".join(remaining) + ("\n" if remaining else ""))

    with open(LOG_PATH, "a", encoding="utf-8") as f:
        f.write(f"{datetime.datetime.now().isoformat()} POSTED: {text}\n")

    print("posted:", text)


if __name__ == "__main__":
    main()

3. register_task.ps1（毎日9:00/21:00に自動実行）

# 毎日9:00/21:00に投稿スクリプトを実行するタスクを登録する（PowerShell / 管理者権限不要）
# 実運用中の設定値（絶対パス・StartWhenAvailable・WakeToRun）をそのまま再現している。
$project = "C:\path\to\your-project"            # ← 自分のプロジェクトのパスに変える
$py      = "C:\Users\YOU\AppData\Local\Programs\Python\Python312\python.exe"  # ← 素の "python" は不可。絶対パスで指定
if (-not (Test-Path $py)) { throw "python.exe が見つかりません: $py" }

$action   = New-ScheduledTaskAction -Execute $py `
              -Argument "$project\marketing\daily_post.py" `
              -WorkingDirectory "$project\marketing"
$triggers = @(
  (New-ScheduledTaskTrigger -Daily -At 9:00),
  (New-ScheduledTaskTrigger -Daily -At 21:00)
)
# StartWhenAvailable: 時刻にPCがオフ/スリープでも、復帰後に実行する（これが無いと機会を逃して二度と動かない）
# WakeToRun: スリープから起こして実行する
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -WakeToRun `
              -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries

Register-ScheduledTask -TaskName "DailyPost" -Action $action -Trigger $triggers -Settings $settings -Force

# 動作確認（登録直後に1回手動実行して、結果コード0か見る）
#   Start-ScheduledTask -TaskName "DailyPost"
#   Get-ScheduledTask -TaskName "DailyPost" | Get-ScheduledTaskInfo | Select LastRunTime,LastTaskResult
#   LastTaskResult が 0 以外なら失敗。2147942402(=ERROR_FILE_NOT_FOUND) は python のパス解決失敗。

  "https://api.github.com/repos/$REPO/traffic/popular/referrers"

5. deploy_page.sh（git無しで本番サイトを更新）

#!/bin/bash
# GitHub Contents API で1ファイルを本番(GitHub Pages)へデプロイする。git不要、curlとpythonだけで動く。
# 使い方: bash deploy_page.sh <ローカルファイル> <リポジトリ内パス>   例: bash deploy_page.sh site/index.html index.html
set -e
set -a; . ./.env; set +a
REPO="YOUR_GITHUB_USER/YOUR_REPO"
SRC="$1"; DEST="$2"
API="https://api.github.com/repos/$REPO/contents/$DEST"

# 既存ファイルのsha(更新に必須)。新規作成の場合は空でよい
SHA=$(curl -s -H "Authorization: token $GITHUB_TOKEN" "$API" \
      | python -c "import sys,json;print(json.load(sys.stdin).get('sha',''))")

python - "$SRC" "$SHA" "$DEST" > payload.json <<'EOF'
import sys, json, base64
src, sha, dest = sys.argv[1:4]
body = {"message": f"update {dest}", "content": base64.b64encode(open(src, "rb").read()).decode()}
if sha:
    body["sha"] = sha
print(json.dumps(body))
EOF

curl -s -X PUT -H "Authorization: token $GITHUB_TOKEN" -d @payload.json "$API" \
  | python -c "import sys,json;d=json.load(sys.stdin);print(d.get('commit',{}).get('sha') or d.get('message'))"
rm -f payload.json

6. CLAUDE.md 雛形（AIに事業を任せる運営ルール）

予算・承認フロー・実測ルール・投稿ルール。「AIに任せる範囲」と「人間が握る範囲」の線引きが、この雛形の核心です。

# CLAUDE.md（AIに事業を任せるときの運営ルール雛形）

## 役割
- Claude が CEO として全体を統括し、最終判断を行う。
- 必要に応じて Sales / Marketing / Finance / Research のサブエージェントに意見を求めるが、決めるのはCEO。
- 重要判断は DECISIONS.md に「理由・選択肢・撤退条件」付きで記録する。着手前に同種の過去判断がないか確認する。

## 予算
- 初期資金：__円（絶対上限、超過禁止）。残予算は BUDGET.md の値を正とし、過去分を遡って再計算しない。
- 支出は少額でも「目的・金額・期待効果」をセットで BUDGET.md に追記する。
- 売上は手数料控除前のgrossで記録し、手数料は経費側に計上する。

## 承認フロー（ここが人間の仕事）
- 次に該当する取り消しが難しい金銭操作は、実行前に必ず人間の承認を取る：
  追加課金 / 新規契約・サブスク / 外部サービスへの支払い
- 上記以外（コンテンツ作成・投稿・サイト更新など決済が絡まない作業）はCEO判断で進めてよい。
- 本人確認・アカウント作成・個人の識別情報に関わる変更（ユーザー名、プロフィール等）はCEOが勝手に行わず、選択肢を提示して人間に判断を委ねる。

## 実測ルール
- 「多分こう」で判断しない。判断の前にAPIで実測する（訪問数・決済数・投稿のimpression）。
- 実測できない数字を出すときは「仮定」と明記する。売上見込みを断言しない。
- 毎日、KPIとサイトの数字を更新する。悪い数字も隠さず載せる。

## 投稿ルール（X）
- 実質文字数の上限は全角換算で約140字（加重文字数）。280字ではない。余裕を見て130字程度に収める。
- URL付き投稿は課金が高い（実測 $0.20/件 vs URLなし $0.015/件）。本文にはURLを入れず、必要なときだけ自己リプに分離する。
- 投稿スクリプトは「成功したときだけキューから消す」。失敗は例外にして必ずログに残す。

## トークン節約
- 同じ調査を繰り返さない。過去の DECISIONS.md / research/ を先に読む。
- サブエージェントへの依頼には既知の制約（文字数上限など）を必ず明記して、手戻りを防ぐ。

7. 実際に起きた失敗集（14件）

すべて実験中に実際に起きたことです。左が症状、右が対策です。

#何が起きたか対策
1タスクスケジューラが「python」で無音失敗
アクションを素のコマンド名 python で登録したところ、スケジューラ実行時はPATH解決に失敗し ERROR_FILE_NOT_FOUND(2147942402) で何も言わずに落ちた。初日21:00の投稿が未実行だった。		python.exe の絶対パスを指定する。登録直後に Start-ScheduledTask で1回手動実行し、LastTaskResult=0 を確認する。
2PCがスリープ/オフだと二度と実行されない
StartWhenAvailable が False のままだと、時刻に電源が入っていない日は機会を逃してそれきりになる。		-StartWhenAvailable と -WakeToRun を付ける（register_task.ps1参照）。
3投稿失敗が「成功」扱いでキューから消えていた
投稿ヘルパーがHTTPエラーを print して None を返すだけで、呼び出し側は「例外が出なかった＝成功」と見なして投稿文をキューから削除していた。APIが落ちた日は、気づかないまま投稿が消える。2026-09-20に発見・修正。		失敗時は必ず例外を送出し、呼び出し側は例外を捕まえたときキューを消さずログに残す（x_post.py / daily_post.py参照）。
4スクリプトが一時フォルダのファイルに依存していた
自動投稿が、過去のAIセッションの一時ディレクトリにある別ファイルを読み込んでいた。一時フォルダは消えうるので、消えた日に自動投稿が全停止する。2026-09-20に発見・修正。		自動運用に使うコードは全部プロジェクト配下に置く。AIが生成したファイルの置き場所を、必ずレビューする。
5X投稿の文字数上限を誤って伝えられた
サブエージェントが「全角237字まで」と回答。実際は加重文字数で日本語は約140字。3投稿中2投稿が手動トリミングになった。		上限は約140字（余裕を見て130字）。サブエージェントへの依頼文に必ず明記する（CLAUDE.md雛形に記載）。
6URL付き投稿はコストが13倍
URLなし $0.015/件 に対し、URL付きは $0.20/件。毎回URL付きにすると、プリペイド残高が約2週間で尽きる計算だった。		本文にURLは入れない。必要な回だけ自己リプにURLを分離するか、プロフィール/固定ポストに誘導する。
7固定ポストをAPIで設定できなかった
Pinned Tweets APIが404。契約プランでは使えなかった。		人間の1タップに切り出す。自動化できない箇所は、最初から「人間の1操作」として設計に書いておく。
8本番のStripe書き込みがAIの安全装置でブロックされた
50%オフクーポンのPromotion Code作成が、Claude Codeの安全装置（本番書き込み）に止められた。		無理に回避せず、ダッシュボードでの手順を人間に渡す。クーポン本体はAPIで作れるが、有効化に人手が要る場合がある。
9個人の日常アカウントを事業用に転用した
個人の日常投稿と事業投稿が同じタイムラインに混在し、ユーザー名もブランドと不一致。訪問者から見ると信頼性を損なう。		事業用アカウントは分ける。個人の識別情報（ユーザー名等）の変更はAIが勝手にせず、人間に判断を委ねる。
10サイト訪問が14日連続で0だった
決済ページも商品もあるのに誰も来ていなかった。「投稿する」ことと「集客できている」ことは別だった。		毎朝 check_kpi.sh で訪問・決済を実測する。訪問0のうちは、価格や商品を触る前に流入経路を直す。
11プロフィールに導線が無かった
告知投稿にリンクが無く、プロフィールURLは別用途（note）のまま。興味を持っても購入に辿り着けなかった。		投稿→（固定ポスト/自己リプ）→サイト、の最短経路を確認してから投稿を増やす。
12OGPが無く、リンクが素の青文字になる
og:title/og:description/twitter:card が無いと、Xでリンクを貼ってもカード表示にならない。		サイトの head にOGPメタタグを入れる。
13「毎日更新します」と書いて更新していなかった
サイトに約束を書いたまま数字が古くなっていた。		毎朝のチェックで数字を更新してデプロイするところまで、手順に組み込む（deploy_page.sh）。
14Windows固有の落とし穴
PowerShell 5.1 は日本語レスポンスを表示時に文字化けさせることがある（実データは正しい）。Git Bashで schtasks を叩くと /フラグ がパス変換される。		文字化けはUTF-8で手動デコードして確認する。Windowsネイティブコマンドは PowerShell から実行する。
